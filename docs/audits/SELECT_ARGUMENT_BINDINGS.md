Previously, SelectBuilder declared its typed invoke templates without definitions. SelectImplementation's Clause2 binding reinterpreted a parameter value as a pointer and cast result pointer bits into Q. Ordinary structured values could not instantiate that implementation. Its Clause1 implementation existed only on the concrete class, leaving the public builder's corresponding method undefined.

`src/kotlinx/coroutines/selects/Select.hpp:411,431` defines the public typed bindings. The actual registration algorithm is reached through the erased virtual binding at :467,:975 because C++ member templates cannot be virtual. Concrete source invoke methods remain at :960,:966 and forward to those bindings. No select state transition algorithm is replaced.

Clause2 parameters transfer into owned P storage. The block retains that storage through registration, waiting, re-registration and result processing. Value result processors transfer an owning Q box to the receiving block adapter, which releases it on success or exception. Clause2 pointer results remain borrowed and are neither adopted nor deleted. Pointer members in an owned parameter box remain borrowed unless their existing type itself owns the pointee. The cancellation constructor wraps its returned action with the same parameter owner so that prompt cancellation during dispatch cannot release parameter storage before the action reads it.
